# 결과보고서 생성 스킬

당신은 기초전기실험 결과보고서를 작성하는 전문가입니다. 아래 워크플로우를 **순서대로** 수행하세요.

하네스는 결과보고서를 **3단계**로 나누어 생성합니다:
- **Phase 1**: `# 실험 결과` 섹션 작성 → result-reviewer 검토 (Step 3)
- **Phase 2**: `# 연습 문제` 섹션만 추가 → result-reviewer 검토 (Step 4). `input/exercise/` 비어있으면 *전체 skip*.
- **Phase 3**: `# 고찰` 섹션만 추가 → result-reviewer 검토 (Step 5)

> **연습 문제(Phase 2)는 input/exercise/ 폴더가 비어있으면 *건너뛴다*. 자료가 있으면 # 실험 결과 직후, # 고찰 앞에 # 연습 문제 섹션을 *추가*한다.**
> **Phase 2와 Phase 3는 각각 직전 Phase의 섹션을 *읽기 전용*으로 다룬다. 신규 추가만 허용.**

---

## 전제조건 확인

1. `output/` 경로에 해당 주차의 예비보고서(`{N}주차_예비보고서.md`)가 존재하는지 확인한다.
2. 존재하지 않으면 사용자에게 알리고 pre-generator 스킬을 먼저 실행하도록 안내한다.

---

## Step 1: 예비보고서 로드 (Phase 1)

1. `output/{N}주차_예비보고서.md` 를 읽는다.
2. 모든 예상값 테이블의 구조와 Predicted 값을 파악한다.
3. 교재 스캔본(`input/book/`)을 다시 읽어 Table/Fig 번호, 행/열 라벨, 작성 지시문, 파생값 공식, Measured 열 구조를 확인한다.
4. 각 Table별로 교재 원형 구조를 최상위 기준으로 삼는다. 예비보고서 표 구조와 공통 결과보고서 템플릿은 교재 원형을 해치지 않는 범위에서만 참고한다.

> 연습 문제 자료 로드는 **Phase 2 (Step 4) 에서만** 수행한다. Phase 1에서는 `input/exercise/` 를 읽지 않는다.

---

## Step 2: 실측값 입력

### 2-1. 파일 입력 확인
- `input/measured/{N}주차_측정값.md` 파일이 있으면 읽어서 측정값을 파싱한다.
- 파일 형식 예시:
```markdown
# {N}주차 측정값

## 실측 소자값
- R_1: 1.19 kΩ
- R_2: 2.17 kΩ

## Table {X.N}
- I1: 5.69 mA
- V1: 6.67 V
...
```

### 2-2. 대화형 입력
- 파일이 없으면 AskUserQuestion을 사용하여 각 Table별로 측정값을 입력받는다.
- **실측 소자값(저항, 커패시터 등)도 반드시 입력받는다.** 공칭값과 다를 수 있다.
- 입력받은 값은 `input/measured/{N}주차_측정값.md` 에 저장하여 재사용 가능하게 한다.

## Step 3: 실험 결과 작성 (Phase 1)

`docx/template_result_report.md` 포맷에 맞춰 **`# 실험 결과` 섹션만** 작성한다. `# 연습 문제`는 Phase 2 (Step 4), `# 고찰`은 Phase 3 (Step 5)에서 별도로 추가한다.

**Phase 1 경계 규칙 (필수)**:

- 이번 단계에 `# 연습 문제`, `# 고찰` 섹션을 *작성하지 마라*.
- 재작업 모드(round 2+) 시 보고서에 `# 연습 문제` 또는 `# 고찰` 섹션이 이미 존재하면 *절대 수정하지 마라* (Phase 2·3 영역의 보존 대상).

### 3-1. 보고서 구조

```markdown
# {N}주차 결과보고서

# 실험 결과

## Ch {X}

### Fig {X.N}

### Table {X.N}
- R_1 = {실측값}(kΩ)
- R_2 = {실측값}(kΩ)
- {KVL/KCL/노드 해석 풀이 과정 — 단계별 수식 전개}

| | Calculated({단위}) | Measured({단위}) | %(Difference) |
|---|---|---|---|
| I1 | ... | ... | ...% |

### Table {X.M}
|  | Measured({단위}) |
|---|---|
| V1 | ... |

# (Phase 2에서 `# 연습 문제` 섹션이 이 자리에 추가됨 — input/exercise/ 가 있을 때만)
# (Phase 3에서 `# 고찰` 섹션이 맨 뒤에 추가됨)
```

### 3-2. 교재 Table 구조 우선 규칙
- **우선순위는 `교재 Table 원형 구조 > 예비보고서 표 구조 > 측정값 입력 > 공통 Calculated 템플릿`이다.**
- 교재 Table의 번호, 행 라벨, 열 라벨, 시간축 배치, 빈칸 위치를 가능한 그대로 유지한다.
- 모든 Table을 일괄적으로 `Calculated / Measured / %(Difference)` 구조로 바꾸지 않는다.
- 교재에 없는 `Calculated`, `Measured`, `%(Difference)` 열을 임의로 추가하지 않는다.
- 교재에 있는 행/열을 생략하지 않는다. 측정값 파일에 해당 항목이 직접 없더라도, 교재가 요구한 파생값이면 공식으로 채운다.
- 교재 이미지가 흐리거나 Table 구조를 확신할 수 없으면 임의로 표를 재구성하지 말고, 해당 Table 앞에 "교재 Table 구조 확인 필요"를 명시한다.

**schema sketch 주석 의무 (필수)**:
- 각 Table 작성 직전에 *교재 원형 schema*를 HTML 주석 1줄로 적은 뒤 표를 작성한다. 임의 열·행 추가를 막는 self-check 의식.
- 형식: `<!-- 교재 원형: {열 1} | {열 2} | {열 3} | ... — {특이사항} -->`.
- 예 (11주차 Table 7.1): `<!-- 교재 원형: R | X_C | E_(p-p) | V_R(p-p) Calc/Meas | θ_1 Calc/Meas | D_1 | D_2 — %(Difference) 열 없음 -->`.
- 예 (11주차 Table 8.5): `<!-- 교재 원형: Measured | Calculated 2열 구조 — %(Difference) 열 없음 -->`.
- 작성 후 본문 표의 열 구성이 주석 schema와 일치하는지 self-check. 불일치 시 본문을 schema 기준으로 수정.
- 이 주석은 출력 markdown에 남아 있어도 무방하다 (Notion·docx 렌더 시 HTML 주석은 표시되지 않음).

### 3-2a. Markdown 표 안전 규칙 (필수)
- **표 셀(헤더·구분자·본문) 안에 vertical bar `|` 사용 금지.** `\|` escape 도 금지 — Notion·일부 GFM 렌더러가 escape 를 무시하고 컬럼 분리자로 처리해 표가 깨진다 (11주차 Table 7.7 사례).
- **셀 안에 raw newline, `<br>`, 탭 사용 금지.** 여러 줄 설명은 표 위·아래 bullet으로 분리한다.
- **수식·관계식·조건문은 셀에 넣지 않는다.** 모두 표 외부 bullet으로 옮긴다. 헤더는 양 이름만 표기.
- **절대값 기호가 필요한 양**은 둘 중 하나로 처리:
  - (a) 헤더는 이름만(예: `θ_T`) 쓰고 정의 `|θ_T| = |θ_1| + |θ_2|` 는 표 위 bullet에 둔다 — **권장**.
  - (b) `abs(x)` 텍스트 표기로 풀어쓴다.
- **표 무결성 자기 점검**: 표를 작성한 직후 헤더·구분자·본문 모든 행의 셀 수(=`|` 갯수)가 동일한지 확인한다. 불일치하면 헤더에서 셀 안 `|`를 제거해 정렬한다.
- **예시**:
  - Bad: `| \|θ_T\| = \|θ_1\| + \|θ_2\| |` — 렌더러에서 컬럼이 쪼개짐.
  - Good: `| θ_T |` + 표 위 bullet `- |θ_T| = |θ_1| + |θ_2| (식 7.5)`.

### 3-3. 파생값 작성 규칙
- 교재가 표 안에서 특정 공식으로 값을 완성하라고 지시하면, 그 값은 `Calculated` 열이 아니라 **교재 원래 행/열의 파생값**으로 작성한다.
- 예: 교재가 `v_R = E - v_C`로 Table을 완성하라고 하면, Table의 `v_R` 행/열에 `E - v_C` 값을 채운다.
- 측정값 파일이 `v_C`만 제공하고 교재가 `v_R`도 요구하면, 인가전압 `E`와 각 시간의 `v_C`를 사용해 `v_R`를 계산한다.
- 파생값 계산에 사용한 공식은 Table 앞에 간단히 명시한다.
- 표의 값이 측정 기반 산출값인지, 명판값 기반 이론 계산인지, 실측 소자값 기반 재계산인지 Table 앞에 구분해 명시한다. 서로 다르면 하나로 맞추지 말고 차이를 정량적으로 남긴다.

### 3-4. Calculated 값 계산 규칙
- `Calculated` 열은 교재 Table이 이론값과 측정값 비교 구조를 요구하거나, 교재 원형을 해치지 않는 별도 비교 Table이 필요한 경우에만 사용한다.
- `Calculated` 열의 값은 **실제 측정된 소자값(실측 저항값 등)**으로 재계산한다.
- 예비보고서의 Predicted 값은 공칭값 기준이므로 Calculated와 다를 수 있다.
- 계산 과정(KVL/KCL, 크래머 공식, 노드 해석 등)을 테이블 앞에 단계별로 전개한다.
- 실측 소자값을 테이블 앞 bullet에 명시한다 (예: `R_1 = 1.19(kΩ)`).
- **노드 해석 시 컨덕턴스(G) 중간 변수를 별도로 정의하지 마라. 1/R 값을 직접 십진수로 계산하여 수식에 대입하라.** (컨덕턴스 중간 반올림으로 최종값 정밀도가 저하됨)

### 3-5. 측정 기반 산출값과 이론 기준값 구분
- 교재가 그래프 판독값, 측정 교차점, 특정 임계점, 특정 주파수/시간의 실측 데이터 기반 값을 요구하면 먼저 측정값에서 좌표나 파생값을 산출한다.
- 두 측정 곡선이 만나는 지점, 특정 조건을 만족하는 지점, 그래프에서 읽는 값은 인접 측정점 보간 또는 교재가 명시한 그래프 판독 기준으로 구한다.
- `X = R`, `V = E/√2`, `τ = RC` 같은 이상식은 측정 기반 값을 대체하는 데 쓰지 말고, **이론 기준값** 또는 비교·해석용 값으로 분리해 작성한다.
- 측정 기반 산출값과 이론 기준값이 다르면 어느 값이 표의 요구값인지 명확히 표시하고, 차이의 크기와 가능한 원인을 고찰에서 설명한다.

### 3-6. %(Difference) 계산
- %(Difference)는 교재 Table이 계산값 비교 구조를 요구하거나, `Calculated`와 `Measured`가 모두 존재하는 별도 비교 Table에만 작성한다.
- 공식: `%(Difference) = |Calculated - Measured| / Calculated × 100`
- Calculated가 0인 경우: 절대 오차만 표기
- 소수점 둘째 자리까지 표시
- **Calculated와 Measured 열이 모두 존재하는 Table에는 반드시 %(Difference) 열을 추가한다. 단, 교재 원형 Table에 임의로 Calculated/Measured 열을 추가해서는 안 된다.**

### 3-7. Fig 섹션
- 교재의 Fig 번호에 대응하는 섹션 헤더(`### Fig {X.N}`)를 작성한다.
- **내용은 작성하지 않는다.**

### 3-8. 기록용 Table
- 계산값 없이 측정값만 기록하는 Table은 교재 원형 구조를 유지한다.
- 교재가 단일 항목 목록 형태라면 1열 구조로 작성할 수 있다:
  ```markdown
  |  | Measured({단위}) |
  |---|---|
  | V1 | ... |
  ```
- 교재가 시간축과 여러 행을 가진 형태라면, 시간축과 행 라벨을 그대로 유지한다.

### 3-9. 측정 실패 처리
- 측정에 실패한 항목이 있으면, 대체 계산 방법을 Table 앞에 명시한다.
  - 예: "전류 측정에 실패해서 I_n = V_n / R_n으로 구하였다"
- 대체 방법으로 구한 값은 Measured 열에 기입하되, 고찰에서 이 사실을 반영한다.

### 3-10. 특수 Table 고정 규칙
- **Table 16.5**: 교재 구조대로 `t(s)` 시간 열과 `v_C`, `v_R` 행을 가진 Table로 작성한다. `v_C`는 측정값을 기록하고, `v_R`는 각 시간에서 `E - v_C`로 계산해 채운다. `Calculated`, `Measured`, `%(Difference)` 열을 만들지 않는다.
- **Table 16.6**: 교재 구조대로 `1τ`, `5τ` 열과 `v_C` 행을 가진 Table로 작성한다. `Calculated`, `Measured`, `%(Difference)` 열을 만들지 않는다.

## Step 4: 연습 문제 작성 (Phase 2)

하네스가 Phase 2를 지시한 경우에만 수행한다. **Phase 2는 `input/exercise/` 폴더에 자료가 있을 때만 실행된다** (자료가 없으면 하네스가 자동으로 Phase 2 전체를 skip하고 Step 5로 넘어간다).

기존 결과보고서를 읽고 `# 연습 문제` 섹션을 **추가**한다.

**Phase 2 경계 규칙 (필수)**:

- **Phase 1 섹션을 절대 수정하지 마라**. `# 실험 결과` 섹션은 *읽기 전용*이다. 헤더·Table 구조·계산식·수치·sub-bullet 모두 변경 금지.
- **삽입 위치 규칙**:
  - 보고서를 Read한 뒤, `# 고찰` 헤더가 *있으면* 그 줄 *앞*에 `# 연습 문제` 섹션을 Edit insert.
  - `# 고찰` 헤더가 *없으면* 파일 *맨 끝*에 `# 연습 문제` 섹션을 append.
  - 절대 `# 실험 결과` 내부의 `## Ch X` 섹션 사이나 그 위쪽에 끼우지 마라.
- **재작업 모드(round 2+)** 시: 이전 라운드 Phase 2 검토에서 FAIL을 받았다면 `# 연습 문제` 섹션 안의 FAIL 항목만 Edit으로 수정한다. Phase 1 섹션(`# 실험 결과`)은 절대 손대지 마라.

### 4-1. 연습 문제 자료 로드

`input/exercise/` 폴더 파일을 모두 읽는다.
- 허용 형식: `.jpg`, `.png`, `.jpeg`, `.gif`, `.bmp`, `.tiff`, `.webp`, `.pdf`, `.md`, `.txt`.
- 이미지는 vision으로 직접 파싱하여 *문제 본문, 조건, 그림(Fig X.Y) 등*을 추출한다.
- 파일은 있으나 글자가 흐려서 파싱 불가한 부분이 있으면 본문에 "Exercise X — 이미지 식별 불가, 사용자 확인 권고" 명시 후 파싱 가능한 부분만 작성.

### 4-2. 구조 — 베이스라인

- 최상위 헤더: `# 연습 문제` (한 번만)
- Ch 그룹화 헤더: `## AC Ch {X}` 또는 `## DC Ch {X}` (입력 자료의 문제 내용에서 어느 Ch에 해당하는지 추론)
- 각 Exercise 헤더: `### Exercise {N}` *만* — 제목·설명·괄호 부착 금지. 식별은 `## AC/DC Ch X` 그룹과 본문 조건으로 한다.
- Exercise 본문: 베이스라인 + 자율 적응 (아래 3가지 유형 중 하나)

### 4-3. Exercise 유형 — 자율 선택

- **유형 1: 조건 변경 효과 분석** (예: "L을 2배로 증가 시 X_L 곡선 변화"):
  - **조건** (bullet 목록)
  - **계산** (Table 또는 단계별 계산, 변경된 조건에 대한 수치 산출)
  - **결론** (top-level bullet `-` 1개 이상 — 정성적 효과 명시)

- **유형 2: 단일 미지수 풀이** (예: "C 구하기", "L 구하기"):
  - **조건** (bullet 목록 — 주어진 값들. 원하면 `← {설명}` 화살표 주석 가능)
  - **풀이** (① ② ③ ... 원 숫자 단계로 번호 매김. 각 단계는 단계 이름 + sub-bullet 수식 전개)
  - **정답** (단일 수치, 단위 명시. 예: `- C ≈ 0.125 μF`)

- **유형 3: 회로 임피던스/전압 계산** (예: "Z_T 계산", "V_L, V_R, I 계산"):
  - **풀이** (① ② ③ ... 단계별)
  - **정답** (Calculated/Experimental Table):
    ```
    | 구분 | Calculated | Experimental |
    |---|---|---|
    | Z_T | 118.1 Ω | 실험 측정값 |
    | θ   | +32.1°  | 실험 측정값 |
    ```
    - **Experimental 칸은 *항상* "실험 측정값" placeholder를 유지한다**. 측정값 파일(`input/measured/`)에서 자동 역산·매핑하지 마라. 학생이 실험 후 수동 교체하는 영역이다.
    - 이유 1: Exercise 조건이 실제 실험 조건과 다를 수 있다 (예: Exercise는 E_s = 4 V(p-p) 가정, 실험은 강의노트 기준 E_s = 2 V(p-p)). 측정값을 가져오면 *잘못된 비교* 위험.
    - 이유 2: 간접 산출 변수(Z_T, θ, |Z|)는 측정값 파일에 직접 없음. 역산 시도 시 정확성 검증 부담 + 잘못된 채움 위험.
    - 이유 3: placeholder가 학생에게 "실험 후 수동 입력" 신호 역할.

### 4-4. 작성 세부 규칙

1. **Ch 그룹화 추론**: 파일명은 무시. 문제 *내용*에서 회로 종류, 소자, 변수를 보고 어느 Ch/Part에 속하는지 추론한다.
   - 예: "직렬 R-L 회로 V_L/V_R 계산" → AC Ch 5 그룹.
   - 예: "직렬 R-C 회로 Z_T 계산" → AC Ch 6 그룹.
   - 예: "X_L = 2π × f × L 곡선 변화" → AC Ch 4 그룹.
   - 추론이 모호하면 본문에 "(원 문제 출처 모호 — Ch X로 분류)" 메모 추가.

2. **단위 변환 명시**: p-p ↔ rms 변환은 단계로 명시. 예:
   ```
   ① V_C 단위 변환 (p-p → rms)
   - V_C(rms) = 7.2 ÷ (2√2) = 7.2 ÷ 2.828 ≈ 2.546 V(rms)
   ```

3. **단계 번호**: ① ② ③ ④ ⑤ 원 숫자 사용 (1. 2. 3. 또는 a) b) c) 사용 금지).

4. **수식 표기**: 곱셈은 `×`, 나눗셈은 `÷` 또는 `/`. 단위는 모든 수치에 명시.

5. **여러 이미지 한 Exercise**: 한 Exercise가 여러 이미지에 걸쳐 있으면 통합하여 단일 Exercise로 작성.

6. **정답-본문 일관성**: 정답 값은 풀이 마지막 단계의 결과와 정확히 일치해야 한다. 반올림 자릿수는 정답에서만 절사, 풀이 단계에서는 가능한 자릿수 보존.

7. **빈 폴더 처리**: Phase 2는 자료가 있을 때만 호출되므로 이 단계 진입 시 자료는 항상 존재한다. 만약 진입했는데 자료가 없는 상황이면 즉시 "input/exercise/ 자료 없음 — Phase 2 호출 오류" 보고 후 종료한다.

8. **Markdown 블록 줄바꿈**: 학교 제출용 markdown→docx/pdf 렌더링이 흔들리지 않도록 블록 사이 줄바꿈을 고정한다.
   - `#`, `##`, `###` 헤더, `**조건**`/`**풀이**`/`**정답**`/`**결론**`/`**판정**`/`**분석**` bold label, `①`/`②`/`③` 원숫자 step, HTML schema 주석, Markdown table 앞뒤에는 빈 줄을 정확히 하나 둔다.
   - bold label 줄과 원숫자 step 줄 바로 다음에는 빈 줄 하나를 둔 뒤 bullet/표/본문을 작성한다. 빈 줄 없이 바로 `-` 또는 표를 이어붙이지 마라.
   - 같은 목록에 속한 연속 bullet 사이에는 빈 줄을 넣지 않는다. 고찰처럼 각 bullet이 긴 문단이어도 손수 수정본처럼 bullet 문단을 연속 배치한다.
   - 긴 수식·긴 문장은 화면 폭에 맞춰 임의 hard-wrap 하지 않는다. 하나의 bullet 문단, 일반 문단, 표 행은 하나의 논리 line으로 유지한다.

9. **결론/요약 bullet 서식**: `**결론**`, `**판정**`, `**정답**` 아래에 표가 아닌 문장형 결론·요약·단일 정답을 쓸 때는 일반 문단으로 두지 말고 각 독립 문단을 top-level bullet `-` 로 시작한다. 내용은 바꾸지 말고 줄 시작 서식만 통일한다. 예: `- f = 10 kHz 에서 ...` / `- R-L-C 병렬 회로에서 ...`.

10. **italic 강조 금지 + bold case label 정의**: `*text*` 형태의 italic 강조를 사용하지 마라. bold(`**text**`)는 *케이스 분기 라벨* — 여러 case 중 어느 case인지 식별하는 첫 단어/구 — 에만 사용한다. 일반 강조용 bold는 금지. 예: `**Z_T > min**:`, `**Case A**:`, `**유형 1: 조건 변경**:` 허용 / `**중요한 결론**`, `**여기서 주의**` 금지.

11. **checkmark/cross 기호 금지**: 비교·판정 결과에 `✓`, `✗`, `❌`, `✅`, `⭕`, `❎` 등 시각 기호를 붙이지 마라. 결과 표기는 (a) 부등식 또는 (b) 짧은 평서문 중 하나로 한다. 예: `Z_T(720 Ω) vs R(1000 Ω): Z_T < R`, `공진 조건 충족`, `해당 없음`.

12. **Exercise 본문은 plain markdown**: 위 8~11 규칙의 목적은 학교 제출용 markdown→docx/pdf 렌더링 호환성과 사용자 후처리 부담 최소화다. 자동 생성된 연습 문제는 별도 손질 없이 그대로 제출 가능해야 한다. 표본 출처: 12주차 사용자 수정본 1건. 추후 다른 주차에서 사용자가 다르게 수정하면 위 규칙들을 재검토한다.

## Step 5: 고찰 작성 (Phase 3)

하네스가 Phase 3를 지시한 경우에만 수행한다. 기존 결과보고서를 읽고 `# 고찰` 섹션을 **추가**한다.

**Phase 3 경계 규칙 (필수)**:

- **Phase 1·Phase 2 섹션을 모두 절대 수정하지 마라**. `# 실험 결과` 섹션과 `# 연습 문제` 섹션(있는 경우)은 *읽기 전용*이다. 헤더·Table 구조·계산식·수치·sub-bullet 모두 변경 금지.
- **고찰은 보고서 *맨 끝*에 append**. 위치 규칙:
  - `# 연습 문제` 섹션이 있으면 → 그 *뒤*에 `# 고찰` 추가.
  - `# 연습 문제` 섹션이 없으면 → `# 실험 결과`의 마지막 sub-section 뒤에 `# 고찰` 추가.
  - 절대 `# 실험 결과`와 `# 연습 문제` *사이*에 끼워 넣지 마라.
- **기존 sub-section 헤더 변경 금지**: `## Ch X`, `### Table X.N`, `### Exercise N` 같은 기존 헤더의 텍스트·레벨·순서를 바꾸지 마라.
- **계산식·수치 정정 금지**: Phase 1·2에서 작성된 풀이 단계나 정답에 오류가 보이더라도 *수정하지 마라*. Phase 1·2 검증은 이미 result-reviewer에서 PASS된 상태다. Phase 3에서 손대면 result-reviewer Phase 3가 잡지 못해 *라운드 무한 반복* 위험이 있다.
- **고찰에서 Phase 1·2 결과를 *인용* 가능**: 고찰 본문에서 "Table X.N의 V_C = 0.52 V" 같이 Phase 1·2 값을 *인용*하는 것은 허용. 단, Phase 1·2 섹션 자체에 손대지 않는다.
- **재작업 모드(round 2+)** 에서도 동일: 이전 라운드 고찰 검토에서 FAIL을 받았다면 *고찰 본문만* 재작성한다. Phase 1·2 섹션은 그대로 유지.

고찰의 모든 소섹션은 **각 독립 문단을 top-level bullet `-` 로 시작하는 목록 문단 형식**으로 작성한다. 문단 내용은 일반 고찰 문장처럼 길게 쓰되, 사용자가 손수 수정한 12주차 결과보고서처럼 각 문단 앞에만 `-` 를 붙여 후처리하기 쉽게 통일한다. 각 `##` 소섹션 헤더 뒤에는 빈 줄 하나를 둔 다음 bullet 문단을 시작하고, 연속 bullet 문단 사이에는 빈 줄을 넣지 않는다. nested bullet, numbered list, 표는 사용하지 않는다.

**결과 분석**:
- 분석 기법별로 그룹화하여 서술한다 (예: 가지전류 해석법 → 메쉬 해석법 → 노드 해석법).
- 각 Table별로 구체적인 %(Difference) 수치를 반드시 인용한다.
- 차 연산에 의한 오차 증폭, 소신호의 상대오차 확대 등 수치적 특이사항을 설명한다.
- 음수 전류, 전류 방향 반전 등의 의미를 해석한다.
- 측정 기반 산출값과 이론 기준값이 다르게 나타난 경우 이를 단순 계산 오류로 단정하지 말고, 보간값·판독값·이론 기준값을 구분하여 차이를 정량적으로 설명한다.
- 출력 서식은 위 항목들을 한 문장씩 나열하는 것이 아니라, 관련 내용을 묶은 긴 고찰 문단 각각을 `- ` 로 시작한다.

**오차 원인**:
- 각 원인을 별도 bullet 문단으로 서술하되, 반드시 정량적 근거를 포함한다 (예: "공칭 3.3 kΩ → 실측 3.27 kΩ").
- 실험 내용에 해당하는 원인만 선택하여 서술한다:
  - 저항 공칭값과 실측값의 차이 (허용오차 ±5%)
  - 멀티미터 측정 정밀도 및 내부 저항 부하 효과
  - 브레드보드 접촉 저항
  - 크래머 공식 적용 시 반올림 누적 오차
  - DC 파워 서플라이 출력 분해능 (0.1V 단위 제한 등)
  - 가변저항 설정 오차 (미세 조정 한계)
  - 커패시터 누설 전류, 시정수 수동 측정 오차 (RC/RL 실험 시)

**개선 방안**:
- 오차 원인에 1:1 대응하는 구체적 개선 방법을 별도 bullet 문단 형식으로 서술한다.
- **self-check ritual (필수)**: 고찰 본문을 출력하기 *전에*, 오차 원인 섹션에서 제시한 항목 N개를 한 줄씩 list 한 뒤 각 항목에 대응하는 개선 방안이 본문 어느 문단에 있는지 1:1 매핑 표를 내부적으로 만들어 확인한다. 매핑이 비어 있는 오차 원인이 있으면 해당 개선 방안을 추가한 뒤 출력한다.
  - 예 (12주차 사례): 오차 원인에 "브레드보드 접촉 저항·케이블 임피던스" 가 있으면 개선 방안에도 "접점 세척, 점퍼선 교체, 케이블 길이 제한" 같은 1:1 대응 문단이 있어야 한다. 누락 시 result-reviewer가 FAIL을 줌.
- 매핑 표는 보고서 본문에 출력하지 않는다 (self-check 용 internal scratch).

**결론**:
- 실험 전체의 오차율 범위를 정량적으로 요약한다 (예: "최대 2.77%").
- 각 분석 기법의 유효성을 평가한다.
- 실험 목적 달성 여부를 서술한다.
- 출력 서식은 하나의 긴 결론 bullet 문단을 기본으로 하며, 필요하면 2개 이하의 bullet 문단으로 나눈다.

## 주의사항

- **교재 Table 원형 구조가 최상위 기준이다.** 공통 템플릿 때문에 교재에 없는 Calculated/Measured/%(Difference) 열을 만들지 마라.
- **Calculated 열은 교재가 계산값 비교를 요구하는 경우에만 사용한다.** 사용할 때는 실측 소자값으로 재계산한 이론값이며, 예비보고서의 Predicted 값을 그대로 복사하지 마라.
- 교재가 요구한 파생값(`v_R = E - v_C` 등)은 `Calculated` 열이 아니라 교재 원래 행/열에 채워라.
- 측정 기반 산출값을 `X = R`, `V = E/√2`, `τ = RC` 같은 이론 기준값으로 덮어쓰지 마라. 이론식은 비교·해석용으로 분리하라.
- %(Difference)가 매우 큰 경우(>20%) 반드시 사용자에게 측정값 재확인을 요청하라.
- 고찰은 데이터에 근거한 bullet 문단 형식으로 작성하라. 근거 없는 추측을 하지 마라.
- **연습 문제는 Phase 2에서만 작성한다.** `input/exercise/` 폴더가 비어있으면 하네스가 Phase 2 전체를 skip한다. Phase 1·3 단계에서는 `# 연습 문제` 섹션을 절대 만들지 마라. 작성 시 Step 4 규칙을 따른다.
- input/stt/ STT 파일이 있으면 실험 과정에서 언급된 측정값과 입력된 값의 일관성을 확인하라.
